# Documento de Arquitectura: Sistema RAG Multi-Tenant (Serverless)

**Objetivo del Proyecto:** 
Construir un sistema *Retrieval-Augmented Generation* (RAG) escalable y de costo cero (Serverless) que automatice la extracción de contenido web, su vectorización semántica y su disponibilización. 

**Requisito Crítico (Multi-Tenancy):** El sistema debe soportar múltiples clientes/dominios simultáneamente. Los datos de un cliente A *jamás* deben mezclarse ni ser consultables cuando se responde a una pregunta sobre el cliente B.

**Stack Tecnológico:**
*   **Ingesta:** GitHub Actions, Node.js, Cheerio, Turndown, LangChain.js.
*   **Vector DB:** Pinecone (Free Serverless Tier).
*   **Modelos de IA:** Google Gemini API o OpenAI API.
*   **Consulta (API/UI):** Next.js (Edge Functions) desplegado en Vercel.

---

## 1. Estrategia de Aislamiento Multi-Tenant (Namespaces)

Para cumplir con el requisito de no mezclar clientes, **NO** crearemos una base de datos o índice nuevo por cliente (la capa gratuita de Pinecone solo permite 1 índice). 

**La solución es usar Pinecone Namespaces.** 
Dentro de un único índice (ej. `seo-rag-index`), guardaremos los vectores particionados por un `namespace` único (ej. `cliente-libranza` o `cliente-taoporelmundo`).
*   Al hacer *upsert* (guardar), el script debe especificar a qué namespace va.
*   Al hacer *query* (consultar), la API debe restringir la búsqueda a ese namespace exacto.

## Fase 1: Configuración de Infraestructura

1.  **Pinecone:** 
    *   Crear un índice Serverless.
    *   Métrica: `Cosine`. 
    *   Dimensiones: `1536` (si usamos `text-embedding-3-small` de OpenAI) o `768` (si usamos `text-embedding-004` de Gemini). *Nota: Elegir uno y no cambiarlo jamás.*
2.  **API Keys:** Generar `PINECONE_API_KEY` y la clave del LLM (`OPENAI_API_KEY` o `GEMINI_API_KEY`).
3.  **GitHub Secrets:** Inyectar todas las variables en los *Secrets* del repositorio.

---

## Fase 2: Motor de Ingesta (El Scraper en GitHub Actions)

**Objetivo:** Automatizar la extracción de la web y el poblado de Pinecone de forma aislada.

1.  **Input del Workflow:** El archivo `.github/workflows/ingesta.yml` debe tener un `workflow_dispatch` que pida dos parámetros manuales:
    *   `target_url`: La URL base a scrapear.
    *   `client_namespace`: El identificador único del cliente (ej. `cliente-a`).
2.  **Pipeline Node.js:**
    *   **Cheerio:** Extraer solo el `<main>` o `<article>` (ignorar nav/footer).
    *   **Turndown:** Convertir a Markdown.
    *   **LangChain Splitter:** Usar `RecursiveCharacterTextSplitter` (chunkSize: 1000, chunkOverlap: 150).
    *   **Embeddings & Upsert:** Generar los vectores y subirlos a Pinecone asegurándose de pasar el parámetro `namespace: process.env.CLIENT_NAMESPACE`.
    *   **Metadata:** Todo vector debe incluir: `{ url: "...", h1: "...", text_chunk: "..." }`.

**Hito de Validación 2:** Ejecutar el workflow para el "cliente A". Verificar en la consola de Pinecone que los vectores se guardaron bajo el namespace correcto y que el texto plano (chunk) es legible en la metadata.

---

## Fase 3: Backend de Consulta (La API de Recuperación en Vercel)

**Objetivo:** Crear el endpoint POST que reciba la pregunta y recupere el contexto.

1.  **Ruta de Next.js:** Crear `app/api/chat/route.ts` usando el runtime de Edge (`export const runtime = 'edge'`).
2.  **Contrato del Request:** El endpoint debe exigir el `namespace` en el body de la petición para saber en qué "cajón" buscar.
    ```json
    {
      "query": "¿Cuáles son los requisitos?",
      "namespace": "cliente-libranza"
    }
    ```
3.  **Búsqueda (Retrieval):** 
    *   Vectorizar la pregunta del usuario (`query`).
    *   Hacer un `similaritySearch` en Pinecone pasando explícitamente el `namespace`. Requerir `top_k: 4`.
4.  **Generación (LLM):**
    *   Extraer el texto de la metadata recuperada.
    *   *System Prompt Estricto:* "Eres un asistente experto. Responde ÚNICAMENTE basándote en este contexto. Si no está en el contexto, di 'No lo sé'. Contexto: [CHUNKS_RECUPERADOS]".
    *   Devolver la respuesta usando *Streaming* para evitar los timeouts de Vercel (10 segundos a 15 segundos max).

## Fase 4: Interfaces (UI Web y API Headless)

**Objetivo:** Disponibilizar el sistema tanto para humanos en la web como para agentes en la terminal (Claude Code, OpenCode).

### A. Para Humanos (Chat UI)
*   Crear una interfaz en React/Tailwind.
*   En el código de la UI, debe haber una forma (ej. variable de entorno del frontend o un menú desplegable oculto) para que la UI sepa qué `namespace` enviar en cada petición POST al backend.
*   *Requisito:* La UI debe renderizar las fuentes (URLs de los chunks utilizados) debajo de la respuesta de la IA.
